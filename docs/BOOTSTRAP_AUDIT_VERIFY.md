## §12 findings — what SPLIT_PLAN actually requires

**(a) Is the SLA compiler to be rewritten in SLA and compiled by the current compiler?**
Yes in scope, staged in form. The plan's main body (§2.3) ports the compiler's product modules to SLA in 12 stages (0–11), and §6 defines the end state: "设 A = Zig 构建的现行插件 .so（stage0），B = 全部产品模块由 SLA 构建的插件 .so（stage1）", with 验证一 (self-compile): "用 B 作为 SA 宿主的 sla 插件，编译编译器自身的全部 SLA 源码，产出 B′（stage2）". So the SLA-written compiler is first built by stage0 (the tagged Zig build), then compiles itself. The scale exposure is therefore real, but it is the plan's explicit subject, not an unexamined assumption: per-stage name-set gates (§3), and §7 pre-registers partial outcomes — R1 (the parser/lowering_rules/type_checker SCC团， 21,835 lines, may stay in Zig, with the bootstrap status "显式降级登记"), R6 (untranslatable Zig-idiom modules stay in Zig), R7 (hand-written SA glue for the ABI shell, registered as a non-bootstrapped surface). §9 presupposes this port: "全部模块移植完成后，由 stage0（打 tag 的 Zig 版）把 SLA 编译器编成原生二进制".

**(b) Stated first step.**
§9, verbatim: "开工第一步（探针）：同一批语料 build-js 对 native 计时对拍，先证快再全面推——SAB 教训：未实测不宣称提速。" Ordering rule in the same section: "顺序不变：先收官打 tag、把语义用语料钉成合同，再开自举；本增补不改期、不挤当前清零工作。" (The main plan additionally gates all bootstrap work behind the §5 pre-gate list G1–G7 — all 7 recorded 未关/未执行 in the plan — and its own stage 0 is a lexer port probe, §3.)

**(c) Does the route require a self-authored codegen backend or linker independence?**
No — the opposite is an iron rule. §9: "JS 必须经 SA 宿主 build-js 路（照样过展平 + 所有权验证，检查一分不少，只是换发射目标）；禁止 SLA 直出 JS 绕过 SA 验证". "定位：JS/Bun 只是开发期快验运行时，不是产品目标；产品输出恒为 SA text → native，收官门仍为 native 全量。" The final native binary is produced by stage0 compiling the SLA compiler, and §7 R2 pre-registers that sab_codegen may stay in Zig because the SAB encoder lives in sci. The route deliberately keeps the SA host and the Zig-built stage0 in the loop.

## Where the audit's framing diverges from the settled route (per SPLIT_PLAN text only)

1. **Standalone-ness is a non-goal, not a failed goal.** The audit's obstacle 3 grades SLA on producing a "完全自包含、不依赖 Zig/sa 宿主" toolchain. §6 defines success as B running as the SA host's sla plugin, with acceptance = "发射产物字节相等 + 行为名集相等" and explicitly "不要求 .so 字节相等". Host dependence is the design, so "寄生而非自托管" does not bear on whether the route works.
2. **The route is staged with registered partial outcomes; the audit grades a single all-or-nothing jump.** "先收官打 tag、把语义用语料钉成合同，再开自举", 12 stages with per-stage gates, and §7's stop-loss rule: any module staying in Zig is registered (name, lines, reason, seam) and "自举完成度以登记清单为准". A not-fully-bootstrapped end state is a registrable outcome inside the plan, not a refutation of it.
3. **§9 reframes the practical bottleneck as dev-loop cost, not expressiveness.** The variant exists because "编译器本体每次改动要重编原生插件/cargo（分钟级）" plus per-file LLVM+link cost in corpus validation; the JS/Bun runtime (via the host's build-js path, checks intact) attacks those two costs. The audit's verdict does not consider this route, and §9's own first step is a measurement probe before any porting commitment.
4. **One of the audit's obstacle-1 premises is factually stale.** The "无 defer" item (claim 3, REFUTED) comes from a 2026-07-01-snapshot page; the goroutine syntax batch has since landed defer, and the plan's stage 1 already lists `defer_desugar` among the modules to port.
